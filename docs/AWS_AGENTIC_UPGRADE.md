# AWS + Agentic AI extension

This extension adds optional cloud orchestration and an optional Amazon Bedrock copilot without changing the Studio's validated analytical core.

## Design principle

The Studio keeps a strict separation between numerical truth and generated language:

```text
validated local/market evidence
        ↓
deterministic Python engine
        ↓
validated facts + provenance
        ↓
optional Bedrock interpretation
```

The LLM does not replace battery, market, finance or risk calculations. If Bedrock is disabled, unavailable or cannot find grounded evidence, the existing deterministic Stage 21 analyst remains fully functional.

## Bedrock evidence copilot

`engine/bedrock_analyst.py` adds a tool-calling layer around the existing evidence registry. The model can request `search_studio_evidence`, but the tool result is generated by the deterministic `answer_evidence_question()` function.

The UI always presents the validated answer separately from any Bedrock interpretation. Sources, formulas and limitations continue to come from the evidence registry.

## Local Bedrock configuration

Use temporary/local AWS authentication; do not put credentials in the repository.

```powershell
aws login --profile energy-ops --region eu-west-2
$env:RFS_BEDROCK_ENABLED="1"
$env:RFS_AWS_PROFILE="energy-ops"
$env:RFS_AWS_REGION="eu-west-2"
$env:RFS_BEDROCK_MODEL_ID="amazon.nova-lite-v1:0"
python app.py
```

When `RFS_BEDROCK_ENABLED` is absent or false, no Bedrock call is attempted.

For a hosted AWS deployment, prefer an IAM role with only the required `bedrock:InvokeModel` permissions. A Render deployment should keep the Bedrock feature disabled unless a secure short-lived credential mechanism is available; long-lived keys should not be committed or embedded in code.

## Cloud release publishing

`cloud/s3_publish.py` builds a release manifest for selected validated forecast/market artefacts. Every entry includes path, byte size and SHA-256 checksum. The publisher uploads the artefacts and a compact `manifests/latest.json` object to S3 using server-side AES256 encryption.

The core application does not require S3. This path is deliberately additive so the validated local/GitHub workflow still works if cloud publishing is unavailable.

## Airflow orchestration

`airflow/dags/rfs_cloud_pipeline.py` defines three explicit tasks:

```text
validate_bundle
      ↓
publish_bundle
      ↓
verify_bundle
```

The validation task builds checksum/size metadata. The publish task writes the validated release to S3. The verification task re-reads each published object and checks both byte size and SHA-256 checksum. Retries are configured at DAG level.

Only compact manifest metadata is passed between tasks. Large CSV/JSON artefacts remain in files/S3, which keeps the workflow suitable for production-style orchestration.

Required environment variables:

```text
RFS_S3_BUCKET=<private bucket>
RFS_S3_PREFIX=renewable-flexibility-studio
RFS_PROJECT_ROOT=<repo path, optional when DAG lives in this repo>
RFS_RELEASE_REVISION=<git/release revision, optional>
```

Airflow has its own optional dependencies in `airflow/requirements.txt`; it is not installed by the Render web-app build.

## Evaluation and failure behaviour

The Bedrock layer is tested with fake clients so CI does not require network access or AWS credentials. Tests verify that:

- deterministic evidence remains available when Bedrock is disabled;
- the LLM must request the controlled evidence tool before a hybrid answer is produced;
- hidden `<thinking>` content is stripped from displayed text;
- a Bedrock failure returns the deterministic answer instead of breaking the Studio;
- cloud manifests carry checksums and S3 publishing/verification can be tested without AWS.

This follows the lesson from the initial prototype: a correct tool result can still be misinterpreted by generated prose. The production pattern therefore keeps validated facts visibly separate and authoritative.

## Live validation snapshot

On 16 September 2026 the local integration was exercised against the `energy-ops-dev` IAM identity in `eu-west-2`.

- Bedrock/Nova Lite successfully selected `search_studio_evidence` and returned a supplementary grounded interpretation while the deterministic answer remained visible.
- The cloud publisher uploaded 13 compact forecast, reserve, market, investment, finance and risk artefacts to the private S3 release prefix.
- Post-publish verification re-read all 13 objects and confirmed both byte size and SHA-256 checksum integrity.
- The Airflow 3.3.1 DAG is exercised in Ubuntu CI: metadata-database migration, DAG reserialization/discovery and `validate_bundle` task execution pass. The live S3 publish/verify path is validated separately under the least-privilege `energy-ops-dev` IAM identity; CI stores no AWS credentials.
